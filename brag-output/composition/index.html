The team

plannerreads the question, writes the work plan, splits it into sub-queries
searchers ×4rank the bundled 20-document corpus — TF-IDF: word frequency, weighted by rarity
readersread the found documents, extract claims — short factual sentences with a location
analystmerges claims, removes duplicates, cross-checks them against each other
criticthe quality gate — verifies receipts, measures evidence coverage, orders more search if thin
writercomposes the report — every factual sentence carries a numbered citation [n]
Six roles. One question. One report.
agent A worker with a job description, tools, and just enough judgment for that one job. Here: a plain async function.
TF-IDF search Keyword ranking: score by how often your words appear, weighted up for rare, distinctive words.
coverage check Does the evidence answer every part of the question? A 0-to-1 score with a threshold (0.8).

checkpoint → SQLite, WAL mode every node, the moment it finishes: its output + the fact that it fired. A crash loses the interrupted step — nothing more.

execution counters: finished nodes ran exactly once — only read-1 ran again
One interrupted step redone — that's the entire cost of a crash.
checkpoint A saved snapshot of progress: which nodes finished and what they produced.
SQLite WAL Write-ahead logging: writes hit a log first, so a crash mid-write can't corrupt the record.
resume Restart by loading the last checkpoint. A good resume never redoes finished work.
execution counter A tally of how many times each node really ran — proof, not intentions.

It never picks a winner. It tells you the sources disagree — with both citations attached.
contradiction detection Compare claims about the same entity and attribute — flag numeric mismatches and negations.
entity canonicalization Merge the different names for the same thing — "XK-7", "the XK-7 module", "XK7" become one entity.
corpus The fixed set of 20 bundled documents — with this contradiction planted on purpose.

SwarmResearch · 07/09 · the numbers

Why hand-rolled?

LangGraph, LangChain, CrewAI — all mature. So why build Orchestra?
the honest cost
  • No ecosystem — no community integrations
  • No visual debugger or studio UI on day one
  • You own the edge cases — e.g. a pause cancels in-flight siblings and rewinds them to pending
the payoff
  • ~600 lines, fully auditable, 0 framework dependencies
  • Plain async nodes — no lock-in, no upgrade treadmill
  • Exact checkpoint granularity — the no-recompute guarantee is testable
  • Typed event bus + spans — observable by default
For deep research, the runtime is the product.
"what happens when a node times out mid-retry?" → read one function.
asyncio Python's built-in concurrency for I/O-bound work: many tasks, one thread, awaiting on slow things.
event bus The runtime's live narration of itself: node started / finished / failed / skipped, graph completed.
human-in-the-loop The run pauses at chosen points and waits for a person — the pause survives a restart.
